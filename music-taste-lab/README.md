# 청음실 — 음악 취향 분석 웹사이트

곡·앨범·아티스트를 검색해 담으면 세부장르, 작곡·작사·프로듀서 크레딧, 곡의 느낌(템포·조성·에너지·밝기·공간감), 8개 항목 엄격 채점, 그리고 담은 음악 전체를 묶은 취향 공식을 보여 주는 정적 웹사이트입니다.

## 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대 |
| `style.css` | 블랙 테마 스타일 |
| `engine.js` | 검색·메타데이터 조회·브라우저 내 오디오 분석·채점 |
| `app.js` | 화면 렌더링·담기·취향 프로필 |

서버가 없습니다. 방문자 브라우저가 아래 공개 API를 직접 호출하므로, 접속자가 늘어도 이 사이트 쪽에 부하가 몰리지 않습니다. 정적 파일은 GitHub Pages나 Cloudflare Pages의 CDN이 제공합니다.

- 검색: Apple iTunes Search API(JSONP), Deezer API(JSONP)
- 크레딧·세부장르: MusicBrainz API(CC0, 초당 1회 규칙을 큐로 준수)
- 느낌·측정 점수: 30초 미리듣기를 Web Audio로 디코드해 FFT 기반으로 템포(온셋 자기상관), 조성(Krumhansl–Kessler 프로필), 다이내믹 레인지, 스테레오 폭, 스펙트럼 무게중심, 화성 변화율을 계산

## 채점 기준

8개 항목 고정 가중치를 씁니다: 작곡 22, 편곡·사운드 22, 연주·보컬 12, 가사 8, 혁신 10, 통일성 8, 유레카 10, 미적 일체감 8.

- 오디오로 잴 수 있는 작곡(화성 측면)과 편곡·사운드만 자동으로 측정합니다. 근거 없이 4점을 넘지 않고, 작곡은 멜로디를 판정할 수 없어 3.5점이 상한입니다.
- 나머지 항목은 보수적 기본값 2.5점으로 두고 "잠정"으로 표시합니다. 사용자가 막대를 옮겨 직접 채점하면 확정됩니다.
- 인기·차트·수상 기록은 점수에 넣지 않습니다.
- 앨범 점수는 상위 3곡 평균 50% + 통일성 30% + 미적 일체감 20%로 계산합니다. 아티스트 점수는 대표곡 평균 55% + 상위 3곡 30% + 일관성 15%로 계산하고, 대표곡 한 곡에 의존하면 감점합니다.

## 배포 (GitHub Pages)

1. 저장소 Settings → Pages → Build and deployment → Source: **Deploy from a branch**
2. Branch는 이 폴더가 있는 브랜치, 폴더는 `/ (root)`를 고르고 Save를 누릅니다.
3. 1~2분 뒤 `https://<계정>.github.io/<저장소>/music-taste-lab/`로 접속합니다.

## 로컬 실행

```bash
cd music-taste-lab && python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

## 알려진 한계

- 음원 전체가 아니라 30초 미리듣기로 분석합니다.
- Apple 공개 검색 API는 IP당 분당 약 20회로 제한됩니다. 막히면 Deezer 결과만 보여 주고 안내 문구를 띄웁니다.
- 멜론과 Spotify는 공개 검색 API가 없거나 서버 인증이 필요해서, 결과에서 해당 서비스로 바로 가는 링크만 제공합니다.
- 담은 음악은 브라우저 localStorage에 저장됩니다. 백업 파일 내려받기·불러오기를 지원합니다.
